# 儿童牙科候诊玩具消毒与轮换系统

候诊区玩具的投放、回收、清洁、消毒、干燥、破损与隔离全流程管理。
**不保存任何真实患儿信息** —— 系统只登记玩具、候诊区、员工与周转事件。

## 一键启动

```bash
./run.sh          # 初始化 SQLite + 生成演示样例 + 启动服务
# 打开 http://127.0.0.1:8000
```

`run.sh` 首次启动会自动生成演示数据：**材质冲突**（木质玩具误选浸泡）、
**批量隔离**（硅胶批次设备回执污染，3 件整批隔离）、**破损维修**（锐边报损附照片→
维修→待复核；零件缺失待修），以及一条超期未回收（调度器标记“回收漏扫”）。
删除 `data/toys.db` 可重新生成。

```bash
python3 -m unittest discover -s tests -t .   # 运行全部测试（24 个）
```

纯 Python 3 标准库实现（sqlite3 + http.server + threading），无需安装依赖。

## 业务流程

```
清洁库 ──投放──▶ 候诊区 ──回收扫码──▶ 待清洁 ──擦拭/浸泡/机洗──▶ 已清洁
  ▲                                                                  │
  │干燥满规定时长（调度器自动回库）◀── 干燥 ◀── 消毒合格 ◀── 组批提交设备
  │                                                │
  └──── 解除隔离（仅护士长）── 待清洁 ◀── 隔离 ◀── 消毒失败(污染)/报损(锐边·掉件·污染)
```

- 材质决定清洁方式：硬塑浸泡/机洗、毛绒机洗、木质仅擦拭、硅胶浸泡、金属/电子擦拭；
  选错即记“材质不兼容”并拒绝。
- 消毒批次按**材质分组**；模拟设备回执分三种：合格→干燥、失败→退回待清洁、
  污染→**批量隔离**。
- 干燥时长按材质（硬塑60′/毛绒240′/木质30′/硅胶90′/金属45′/电子15′），
  未满时长上架记“干燥提前”并拦截。
- 锐边、掉件、污染风险报损后**立即隔离**，普通清洁不能解除隔离；
  修复后仍需护士长复核解除，解除后回待清洁重新走工序。

## 并发与权限

- 投放排他：`BEGIN IMMEDIATE` + 条件更新（`WHERE status='in_storage'`），
  两名员工并发投放同一玩具仅一人成功；数据库部分唯一索引保证
  同一玩具最多一条进行中投放（不会同时出现在两个区域）。
- 角色：护士长（解除隔离/报废）、护士（投放/回收/报损）、保洁（清洁/消毒/干燥）、
  **前台只能查看候诊区可用数量与轮换时间**（API 层 403）。

## 异常分类（分别记录）

玩具错区 · 回收漏扫 · 材质不兼容 · 消毒失败 · 干燥提前 · 零件缺失 · 批量隔离

## 测试覆盖（tests/）

- `test_deployment_exclusivity.py` —— 投放排他：同玩具不跨区、并发仅一人成功、容量/错区
- `test_process_blocking.py` —— 工序阻断：状态机非法流转、清洁不能解隔离、材质拦截
- `test_drying_boundary.py` —— 干燥边界：提前 1 分钟拦截、恰好到期放行、调度器按时回库
- `test_isolation_permission.py` —— 隔离权限：仅护士长解除、未修复不可解除、前台只读
- `test_batch_traceability.py` —— 批次追溯：污染批次整批隔离、失败退回、漏扫标记

## 页面

洁净白 + 海盐蓝 + 柔和珊瑚，无卡通背景。玩具库为小图标配编号的密集网格；
消毒批次按材质分组；候诊区视图只显示可用数量与轮换时间；
隔离状态同时使用锁形图标与文字。页面右上角切换员工身份体验不同角色权限。
